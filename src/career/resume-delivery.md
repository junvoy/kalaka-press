# 简历投递

投递不是把同一份简历批量发送出去，而是判断岗位匹配度、选择正确版本，并通过记录持续修正策略。

::: info 本章产物
完成本章后，你应该拥有：岗位评分表、JD 匹配矩阵、岗位版简历、首次沟通文案和投递跟踪表。
:::

## 1. 给岗位评分

先评估，再决定是否投入定制和面试准备时间。

| 维度 | 权重 | 判断问题 |
| --- | ---: | --- |
| 核心职责 | 35 | 最近经历是否解决过相似问题？ |
| 必备技术 | 25 | 是否有生产或完整项目证据？ |
| 业务与规模 | 15 | 行业、用户量、并发或数据规模是否接近？ |
| 地点与条件 | 15 | 城市、薪资、到岗方式是否接受？ |
| 信息可信度 | 10 | 职责、团队、业务和招聘流程是否清楚？ |

参考决策：

- `≥ 70`：优先定制并投递。
- `50～69`：有关键亮点时选择性投递。
- `< 50`：除非有明确转型理由，否则降低优先级。

评分是减少盲目投递的工具，不是机械门槛。

## 2. 拆解 JD 匹配矩阵

| JD 要求 | 重要性 | 我的证据 | 证据等级 | 简历动作 | 面试准备 |
| --- | --- | --- | --- | --- | --- |
| Spring Cloud | 必须 | 多个微服务项目 | 生产经验 | 放到首屏 | 准备治理与故障案例 |
| MCP / Agent | 加分 | 已落地 Agent | 生产经验 | 提升项目顺序 | 准备状态机与幂等追问 |
| 某陌生框架 | 加分 | 简单验证 | Demo | 标记为了解 | 只准备基础概念 |

只调整有真实证据的内容。没有证据的关键词不能通过“换个说法”变成生产经验。

## 3. 生成岗位版本

岗位版通常只需要调整：

1. 求职方向和个人优势的顺序。
2. 专业技能中相关关键词的位置。
3. 最匹配项目的顺序、篇幅和标题。
4. 与岗位关系较弱的内容。

保存当时投递版本：

```text
姓名-公司简称-岗位方向-20260821
```

不要覆盖旧文件，否则面试时无法确认对方看到的内容。

## 4. 编写首次沟通

结构：角色定位 + 核心经历 + 一个岗位匹配点 + 沟通意愿。

### Java 后端岗位

```text
您好，我有 6 年 Java 后端经验，参与过多个 Spring Cloud 项目，主要负责高并发、缓存、消息队列和系统稳定性建设。岗位方向与我的项目经历比较匹配，方便的话希望进一步沟通，谢谢。
```

### Java / AI Agent 岗位

```text
您好，我有 6 年 Java 后端经验，并有已投产的 LangChain / MCP Agent 项目，做过工具服务、确定性状态机、幂等和人工复核设计。对贵司岗位很感兴趣，希望进一步沟通，谢谢。
```

首次消息保持短；收到回复后，再补充项目细节、到岗时间和岗位问题。

## 5. 选择投递渠道

| 渠道 | 适合场景 | 注意事项 |
| --- | --- | --- |
| 招聘平台 | 大范围发现岗位、直接沟通 | 信息更新快，需要记录版本 |
| 公司官网 | 目标明确、流程正规 | 反馈可能较慢，保存申请编号 |
| 内推 | 岗位匹配度高、有可靠联系人 | 不要求对方为不匹配岗位背书 |
| 猎头 | 中高级岗位或特定行业 | 确认授权范围，避免重复投递 |

同一公司同一岗位避免多渠道重复提交，以免产生候选人记录冲突。

## 6. 建立投递跟踪表

| 日期 | 公司 / 岗位 | 来源 | 匹配分 | 简历版本 | 联系人 | 当前状态 | 下一步日期 | 结果备注 |
| --- | --- | --- | ---: | --- | --- | --- | --- | --- |
| 2026-08-21 | 示例公司 / Java | 招聘平台 | 78 | Java-v2 | HR A | 已沟通 | 2026-08-23 | 等待约面 |

状态统一为：待评估、待投递、已投递、已沟通、已约面、面试中、Offer、结束。

### 跟进节奏

- 投递当天：确认版本和岗位信息已记录。
- 有已读但无回复：可在 2～3 个工作日后礼貌跟进一次。
- 已约面：立即进入[面试指南](./interview-guide)准备。
- 流程结束：记录原因并进入[面试复盘](./interview-review)。

## 7. 用漏斗判断问题

| 现象 | 优先检查 |
| --- | --- |
| 投递很多、已读很少 | 岗位质量、活跃度、投递渠道 |
| 已读很多、回复很少 | 首屏定位、关键词、首次沟通 |
| 回复不少、约面很少 | 项目证据、岗位匹配度、到岗条件 |
| 面试很多、推进很少 | 面试表达、技术缺口、简历强度 |

每周只调整一个主要变量，例如岗位筛选或首屏定位，才能判断变化是否有效。

## 8. 安全与隐私

- 不在公开页面展示完整手机号、邮箱、住址或证件信息。
- 不向不明身份的联系人发送身份证、银行卡或验证码。
- 对异常收费、培训贷款、先交押金等要求保持警惕。
- 发送简历前检查附件版本，避免带出内部客户、密钥或敏感截图。
- 记录猎头或第三方的投递授权，避免未经确认的批量转发。

## 每周执行节奏

- 周初：筛选并评分本周岗位。
- 每天：定制少量高匹配岗位并记录结果。
- 面试前：冻结该岗位简历版本并准备问题地图。
- 周末：统计漏斗，决定下一周只改哪一个环节。
