# 简历样式

好看的简历不等于装饰复杂。样式的目标是建立清晰的信息层级，让招聘方快速找到求职方向、核心能力、最近经历和代表项目。

::: info 本章产物
完成本章后，你应该拥有：统一的视觉规范、可维护的网页简历、附件导出检查表和隐私分级方案。
:::

## 1. 先通过“十秒阅读”

招聘方快速浏览时，页面应直接回答：

1. 你是谁，目标岗位是什么？
2. 你最强的能力是什么？
3. 最近在哪里工作，承担什么角色？
4. 哪个项目最能证明你适合岗位？

如果必须阅读全文才能找到这些信息，说明层级还不够清楚。

## 2. 建立统一版式

| 元素 | 建议 |
| --- | --- |
| 字体 | 使用稳定、易读的系统字体；中文和英文风格一致 |
| 正文 | 保持舒适字号和行距，不用过浅颜色 |
| 标题 | 模块标题、公司标题、项目标题形成三级层级 |
| 间距 | 同级元素间距一致，不依靠大量空行控制布局 |
| 强调色 | 只用于标题、链接和关键标签，避免多色竞争 |
| 日期 | 统一使用 `YYYY.MM - YYYY.MM` 并保持对齐 |
| 标签 | 技术栈可用标签展示，但不能压过项目结果 |

### 控制内容密度

- 每个自然段只表达一个主题。
- 长职责拆成编号列表，避免连续大段文字。
- 一页中不要同时出现过多边框、阴影和强调色。
- 同一级标题使用相同字号、字重和间距。

## 3. 页面长度与分页

经验较少时优先一页；项目较多或工作年限较长时，可以使用两页或更长的网页版本。不要为了强行压缩页数牺牲可读性。

附件导出时重点检查：

- 标题不要单独落在页尾。
- 同一个项目尽量不要被分页切成难以理解的两部分。
- 页边距、页眉页脚和打印缩放保持一致。
- 表格、标签和英文单词没有异常断裂。

## 4. 网页简历架构

网页简历适合持续维护，推荐把内容和展示分离：

```text
resume.content.ts          # 姓名、技能、经历、项目等内容
ResumePage.vue             # 布局、颜色、响应式和打印样式
index.md                   # VitePress 页面入口与元信息
```

这样修改项目经历时，不需要碰复杂 CSS；调整视觉时，也不会误改简历事实。

### 网页版必须具备

- 响应式布局：桌面端多栏，移动端自动单列。
- 主题适配：使用 VitePress CSS 变量支持深浅色。
- 可访问性：标题层级正确，文本对比度足够，链接含义明确。
- 可分享性：页面标题和描述清楚，路径稳定。
- 可维护性：所有简历正文集中在一个内容文件。
- 隐私保护：公开页面不包含可还原的完整敏感信息。

## 5. 附件版本

招聘平台要求上传文件时，可以从主简历导出附件。每次生成新版本都要重新检查，而不是继承上一版结论。

### 文本检查

- 公司、项目、职位和时间与网页版本一致。
- 数字单位、百分号、中英文空格统一。
- 没有替换字符、乱码和英文异常断词。
- 个人优势与项目详情没有机械重复。

### 视觉检查

- 所有页面都实际渲染查看。
- 没有文字裁切、重叠、黑块或字体缺失。
- 分页自然，最后一页没有明显失衡。
- 在线平台再次导出后，确认没有恢复旧文案。

## 6. 隐私分级

| 信息 | 公开网页 | 定向投递 | 建议处理 |
| --- | --- | --- | --- |
| 姓名 | 可保留或使用昵称 | 保留真实姓名 | 根据公开范围决定 |
| 手机号 | 脱敏 | 完整 | 不在 HTML 属性中隐藏明文 |
| 邮箱 | 脱敏 | 完整 | 公开页面移除 `mailto:` 明文 |
| 年龄、性别 | 可隐藏 | 按需要提供 | 不影响能力判断时无需公开 |
| 期望城市 | 可保留 | 保留 | 属于求职偏好，不是精确地址 |
| 家庭住址、证件号 | 不公开 | 通常也不提供 | 永远不要放在公开页面 |
| 公司内部信息 | 去标识化 | 仍需遵守保密要求 | 不暴露客户、密钥和内部地址 |

::: warning 真正的脱敏
只遮住页面显示不够。如果完整手机号仍存在于 `href`、源码、静态数据或构建产物中，依然属于泄露。
:::

## 7. 发布前视觉检查

- [ ] 桌面端第一屏能看到定位、优势和联系方式状态
- [ ] 390px 左右移动端没有横向滚动条
- [ ] 深色和浅色主题都能清楚阅读
- [ ] 长公司名、项目名和技术标签不会溢出
- [ ] 所有内部链接包含正确的部署前缀
- [ ] 浏览器控制台没有错误或警告
- [ ] 构建产物中不存在未脱敏信息
