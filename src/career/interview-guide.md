# 面试指南

面试准备应围绕简历中的真实项目展开。简历负责给出结论，面试负责解释背景、方案、取舍、个人贡献和结果。

::: info 本章产物
完成本章后，你应该拥有：岗位重点地图、自我介绍、两个项目讲稿、技术追问清单、行为案例和反向提问。
:::

## 1. 从岗位和简历交叉准备

不要从通用题库开始。先建立三列：

| 招聘方关注点 | 简历中的证据 | 必须准备的追问 |
| --- | --- | --- |
| Spring Cloud / 高并发 | 共享出行与 IoT 项目 | 架构、瓶颈、监控、故障和取舍 |
| AI Agent / MCP | 已落地 Agent 项目 | 工具边界、状态机、幂等、安全和效果 |
| 数据治理 | 主数据平台 | 模型、分发、审批、版本和一致性 |

优先准备“岗位重要 + 简历已写”的交叉项，因为这是最容易被连续追问的区域。

## 2. 安排准备节奏

### 面试前 3～7 天

- 完成 JD 与简历交叉矩阵。
- 准备两个代表项目和一个失败案例。
- 根据岗位补齐高频技术知识。
- 进行至少一次录音或模拟面试。

### 面试前 24 小时

- 再读一遍实际投递版本，而不是最新主简历。
- 核对面试时间、形式、会议链接和联系人。
- 复习项目数据口径、个人贡献和关键取舍。
- 准备 3～5 个反向问题。

### 面试前 15 分钟

- 关闭通知，测试网络、摄像头、麦克风和屏幕共享。
- 打开简历、JD、纸笔和必要的项目结构图。
- 不再学习新知识，只复习回答结构。

## 3. 自我介绍

控制在 1～2 分钟：

1. 当前定位与工作年限。
2. 两段最相关的经历。
3. 一个与岗位高度匹配的代表项目。
4. 希望在新岗位解决什么问题。

可复制模板：

```text
您好，我主要从事【方向】，有【年限】经验。最近一段经历主要负责【职责范围】，其中完成了【代表结果】；此前在【业务场景】中负责【相关能力】。与这个岗位最匹配的是【项目】，我在其中主要解决了【问题】，采用【方案】并取得【结果】。我希望下一阶段继续深耕【目标方向】。
```

不要逐行朗读简历，也不要在开场把所有技术栈念一遍。

## 4. 项目介绍

推荐使用六段结构：

| 顺序 | 内容 | 面试官在判断什么 |
| --- | --- | --- |
| 背景 | 为什么要做？谁在使用？ | 是否理解业务 |
| 问题 | 最难的问题是什么？ | 问题复杂度 |
| 方案 | 系统结构和关键技术如何选择？ | 技术深度 |
| 贡献 | 哪些部分由你完成？ | 个人所有权 |
| 取舍 | 为什么没有选其他方案？ | 决策能力 |
| 结果 | 如何验证，仍有什么不足？ | 结果可信度与反思 |

### 三层追问

每个项目至少准备三层：

1. **概览层**：两分钟讲清背景、方案和结果。
2. **实现层**：数据流、核心模块、异常流程和关键代码。
3. **取舍层**：替代方案、限制条件、失败尝试和后续优化。

如果项目数字写在简历中，还要能说明：统计时间、数据来源、基线、计算方式和个人影响范围。

## 5. Java 后端追问地图

### Java 与 JVM

- 并发模型、线程池参数、锁竞争和问题定位
- JVM 内存结构、GC 选择、内存泄漏与线上排查
- 集合、异常、反射、类加载和常用设计模式

### Spring 与微服务

- Spring Boot 启动、自动配置、Bean 生命周期
- 事务失效场景、传播机制与分布式一致性
- Nacos、Sentinel、配置变更、熔断、限流和降级
- 服务拆分、接口幂等、灰度发布与故障恢复

### 数据与中间件

- MySQL 索引、事务隔离、锁、执行计划和慢 SQL
- Redis 缓存一致性、穿透、击穿、雪崩与分布式锁
- 消息可靠性、重复消费、顺序、积压和死信处理
- 监控指标、日志链路、告警分级与故障复盘

回答时必须连接到自己的项目：在哪里遇到、如何定位、为什么这样解决、效果如何。

## 6. AI Agent 追问地图

- 为什么使用 Agent，而不是固定工作流或普通接口编排？
- MCP Service 如何划分，工具输入输出为什么这样设计？
- 状态机如何保证流程确定性和可恢复性？
- 如何处理重复触发、模型幻觉、超时和工具失败？
- 幂等键、业务闸门和审计日志如何设计？
- 人工复核边界如何定义，哪些动作不能自动执行？
- 如何评价 Agent 的正确率、效率、成本和业务收益？
- 哪些能力已投产，哪些只是 Demo 或技术验证？

::: warning 生产经验边界
如果某项能力只做过 Demo，应主动说明验证范围。坦诚边界比把所有内容包装成生产经验更可靠。
:::

## 7. 系统设计题

推荐回答顺序：

1. 澄清用户、流量、数据量、一致性和可用性目标。
2. 给出核心用例和系统边界。
3. 画出主要组件和数据流。
4. 解释存储、缓存、消息和接口设计。
5. 处理扩容、容灾、安全、监控和成本。
6. 说明当前方案的瓶颈与下一步演进。

不要一开始就报技术名词；先明确需求和约束，再选择方案。

## 8. 行为面试

使用 `STAR-L`：情境（Situation）→ 任务（Task）→ 行动（Action）→ 结果（Result）→ 学习（Learning）。

至少准备：

- 一次最困难的问题定位。
- 一次线上故障及后续改进。
- 一次与产品、运营或同事意见不一致的处理。
- 一次主动推动工程规范或效率提升。
- 一个失败或结果不理想的项目决策。

重点讲“我做了什么”和“以后会如何改进”，不要只描述团队过程。

## 9. HR 沟通

提前统一以下信息：

- 离职或求职原因：真实、简短，不攻击前公司。
- 期望方向：与当前岗位一致。
- 到岗时间：给出明确可执行的范围。
- 薪资沟通：先了解岗位范围、职责和整体结构，再给出合理预期。
- 职业规划：说明希望积累的能力与可贡献的价值。

## 10. 反向提问

优先问能够帮助判断岗位的问题：

- 这个岗位入职后三个月最重要的目标是什么？
- 团队目前最大的技术或交付挑战是什么？
- 该岗位如何衡量工作成果？
- 项目的开发、测试、发布和故障复盘流程是什么？
- 当前 AI 能力处于验证、内部使用还是生产业务阶段？

避免在技术面一开始只问福利，也不要询问官网已经明确写出的信息。

## 面试前检查

- [ ] 使用的是实际投递给该公司的简历版本
- [ ] 自我介绍控制在两分钟内
- [ ] 两个代表项目均准备到三层追问
- [ ] 所有量化结果都能解释数据口径
- [ ] 已区分个人贡献与团队成果
- [ ] 已准备失败案例和反向问题
- [ ] 线上面试设备、网络和环境已测试

## 下一步

面试结束后，不论结果如何，都进入[面试复盘](./interview-review)，把问题和反馈转化为下一轮的行动。
