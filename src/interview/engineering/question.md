# 设计模式与工程化面试题

设计模式不是要把每段代码都“模式化”，而是总结在特定问题下可复用的组织方式。本章重点是看见问题后能选简单、可维护的方案。

## 设计原则与常见模式

### 1. 什么是 SOLID 原则？

**面试一句话：** SOLID 是五个面向对象设计原则：单一职责、开闭、里氏替换、接口隔离和依赖倒置，它们共同目标是降低模块耦合，让变化集中在更小范围。

初学时先记住两个实用问题：这个类是否承担了太多无关职责？新增一种实现时，能否通过增加代码而不是修改一大串旧 `if-else`？原则是帮助判断的工具，不是强制拆成大量小类。

### 2. 什么是单一职责原则？

**面试一句话：** 单一职责不是“一个类只能有一个方法”，而是一个类应只有一个导致它变化的主要原因。

例如订单服务既计算金额、又生成 PDF、又发送短信时，不同需求会让同一个类频繁改动。可将通知、导出等职责拆到协作对象中，但不要为了形式把简单逻辑拆成难以追踪的十几个类。

### 3. 工厂模式解决什么问题？

**面试一句话：** 工厂模式把对象创建逻辑集中起来，让调用方依赖抽象而不是散落的 `new` 与类型判断，适合实现类型会随配置、渠道或业务条件变化的场景。

例如支付方式有微信、银行卡、余额时，可以由工厂根据支付类型返回对应的 `PaymentProcessor`。Spring 容器本身也承担了对象创建与装配的工厂角色。

### 4. 策略模式和大量 `if-else` 有什么关系？

**面试一句话：** 策略模式把一组可替换算法封装为共同接口的不同实现，调用方在运行时选择策略，适合规则会持续增加且每种规则相对独立的场景。

不是所有 if-else 都应改成策略。只有两三个稳定分支时，直接判断往往更直观；分支不断增加、每个分支有独立配置和测试需求时，策略更合适。

### 5. 模板方法模式和策略模式怎样区分？

**面试一句话：** 模板方法通过父类固定整体流程，让子类补充某些步骤；策略通过组合选择完整的可替换算法。前者偏继承复用，后者偏组合扩展。

当不同实现“步骤顺序相同、个别步骤不同”时可考虑模板方法；当算法本身可以整体替换时，策略通常更灵活。

### 6. 观察者模式适合什么场景？

**面试一句话：** 观察者模式让事件发布者和多个订阅者解耦，发布者只通知事件，不需要知道每个后续动作；适合订单创建后触发通知、积分、审计等场景。

同步观察者会让主流程等待所有监听器；异步事件或 MQ 能降低耦合，但会引入最终一致、失败重试和幂等问题。不能只因为“解耦”就忽略可靠性。

### 7. 装饰器和代理有什么区别？

**面试一句话：** 两者都包装目标对象；装饰器主要在不改变接口的前提下叠加功能，代理主要控制对目标的访问，例如权限、延迟加载或 AOP 增强。

Java I/O 的 `BufferedInputStream` 是装饰器的常见例子；Spring AOP 代理常用于事务、日志和鉴权。实际代码中边界可能相近，回答时说明“主要意图”即可。

### 8. 单例模式有什么坑？

**面试一句话：** 单例保证一个类在一个范围内通常只有一个实例；Spring 的 singleton 是容器级单例，不等于 JVM 中绝对只有一个对象。单例最常见的问题是持有可变共享状态导致线程安全和测试隔离困难。

无状态 Service 适合容器单例。手写单例还要考虑并发、序列化、反射和类加载器等问题；业务代码通常优先交给 Spring 管理。

## 可测试性、日志与交付

### 9. 单元测试、集成测试和端到端测试有什么区别？

**面试一句话：** 单元测试隔离地验证一个类或函数；集成测试验证组件与数据库、消息等协作；端到端测试从外部入口验证完整流程。它们覆盖范围不同，应相互配合而不是只依赖其中一种。

核心金额计算、状态转换等纯业务规则很适合单元测试。涉及真实数据库、序列化或事务的风险则需要集成测试。测试应稳定、可重复，不能依赖不受控的线上数据。

### 10. Mock 应该怎样使用？

**面试一句话：** Mock 用于替代难以控制、速度慢或有副作用的外部依赖，使测试聚焦当前行为；过度 Mock 会让测试只验证实现细节，重构时频繁失效。

优先 Mock 网络、第三方服务、时钟等边界依赖，而不是把领域对象和每个私有步骤都 Mock 掉。重要交互还要用集成测试验证真实协议和配置。

### 11. 线上日志怎样设计才便于排错？

**面试一句话：** 日志应包含时间、级别、服务实例、关联 ID、业务键和关键状态，采用结构化格式并避免记录密码、令牌、身份证号等敏感数据；异常要保留堆栈和上下文。

日志不是越多越好。高频成功路径应控制级别和采样，错误日志要可告警、可聚合。关联 ID 应在 HTTP、异步线程和消息消费之间正确传递。

### 12. 如何做一次安全的发布与回滚？

**面试一句话：** 发布前完成测试、配置核对、数据库变更评估和监控准备；发布中采用灰度或分批并观察错误率与延迟；发现异常时按预案快速回滚代码或开关，并处理已产生的数据影响。

数据库变更要优先采用向前兼容的方式，例如先加字段、让新旧代码都能工作，再逐步切换和清理。回滚不只是把程序版本降回去，还要确认消息、缓存和异步任务没有留下不一致状态。
