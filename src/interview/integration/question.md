# 配置、调度与数据集成面试题

本章对应简历中的 CAS 对账、主数据配置分发、XXL-JOB、长轮询、SFTP/OSS 与 Excel 批处理。它强调批量流程的正确性、可恢复性与可观测性。

## 配置分发与任务编排

### 1. 配置驱动和硬编码有什么区别？

**面试一句话：** 配置驱动把字段映射、日期偏移、渠道规则等变化放到受治理的配置中，核心引擎保持稳定；硬编码开发快，但渠道或项目差异增多后会导致分支膨胀和发布频繁。

配置不是“无代码就没有风险”。它需要校验、审批、版本、灰度、回滚和测试，否则错误配置会比代码错误扩散得更快。

![配置从录入、审批到客户端刷新和回滚的生命周期](/.image/interview/integration/config-lifecycle/config-lifecycle.svg)

### 2. XXL-JOB 适合解决什么问题？

**面试一句话：** XXL-JOB 集中管理分布式定时任务的调度、分片、失败告警和执行日志，适合多实例环境中需要统一编排的批量任务；业务仍要自行保证幂等和可重跑。

任务调度成功不代表业务已完成。应把任务状态、分页进度、执行次数和错误原因持久化，便于断点续跑和人工排查。

### 3. 定时任务怎样避免重复执行？

**面试一句话：** 通过调度中心的单次分发、数据库唯一任务键或带租约的锁避免同一批次被多个实例同时处理；即便发生重复触发，业务写入仍要使用幂等键兜底。

不要只依赖本机内存标记。进程重启、扩容和网络抖动都会让本机状态失效。

### 4. 长轮询和短轮询如何选择？

**面试一句话：** 短轮询按固定间隔发请求，实现简单但空请求多；长轮询在没有变化时挂起请求，变化发生或超时再返回，适合配置更新、消息提示等低频变更通知。

Spring MVC 中可用 `DeferredResult` 释放 Servlet 工作线程并在配置变更时定向唤醒。服务端仍需要设置合理超时、客户端重连、版本校验和连接上限；长轮询不是 WebSocket，也要评估大量挂起请求的资源消耗。

### 5. SFTP、OSS 和数据库分别适合存什么？

**面试一句话：** SFTP 常用于与外部机构交换文件，OSS 适合存放大文件与归档对象，数据库适合保存可查询的元数据、任务状态和业务明细；文件内容与任务记录应通过可追踪标识关联。

下载文件要校验文件名、大小、摘要和重复处理标识。外部文件可能延迟或重复到达，不能假设“目录里只有一份正确文件”。

### 6. Excel 批处理怎样避免内存和数据质量问题？

**面试一句话：** 大文件应使用流式读取、分批校验和分批写入，避免整表加载；以 openpyxl 等工具处理 Excel 时要进行类型、日期、金额、必填和业务规则校验，并将错误行可定位地反馈。

金额使用 BigDecimal 或最小货币单位整数，不能用 double。错误数据应隔离，不能让一行格式错误直接污染整批结果。

### 7. 对账流水线怎样设计？

**面试一句话：** 可分为数据拉取、内部或外部数据生成、明细核对、汇总计算和差异处理等阶段；每个阶段保留输入版本、状态、进度和结果，使失败任务可以从安全边界恢复。

简历中的 Pull/Gen/Check 分段是解耦思路，不表示所有对账业务都必须采用完全相同的三段命名。

### 8. 历史回刷和失败重试有什么风险？

**面试一句话：** 回刷和重试可能重复写入、覆盖新数据或放大下游压力，因此必须限定范围、记录批次、使用幂等键、区分可重试与不可重试错误，并提供审计和停止开关。

对资金或报表类数据，回刷前还要明确权威来源和业务窗口，避免把“历史口径变化”误当成系统错误。

### 9. 多源数据字段不一致怎样处理？

**面试一句话：** 先定义统一业务模型和字段语义，再通过映射、格式转换、默认值与校验规则适配各渠道；无法自动解释的差异应保留原始值并进入异常运营，而不是静默猜测。

字段映射要版本化。上游新增列、表头变动或日期格式变化都应可检测、可告警。

### 10. 批处理任务应监控哪些指标？

**面试一句话：** 至少监控任务触发与成功率、端到端耗时、处理量、分页或批次进度、失败分类、重试次数、积压量和告警送达情况，并能按任务 ID 追溯输入与输出。

指标的目的不是做大屏，而是在超时、差异扩大或任务卡住时，让人能迅速判断影响范围和下一步动作。

### 11. APScheduler 和分布式调度中心怎么选？

**面试一句话：** APScheduler 适合单应用或小规模 Python 自动化任务；多实例、需要集中运维、分片和故障转移时，更适合使用 XXL-JOB 等分布式调度中心。两者都不能替代幂等、进度和失败补偿设计。

### 12. Flask 和 Spring Boot 在自动化服务中怎样分工？

**面试一句话：** Flask 轻量、适合快速封装 Python 自动化能力与内部接口；Spring Boot 更适合承载复杂 Java 业务、成熟的事务与生态集成。选型应看业务边界、团队栈和运行治理能力，不是语言优劣比较。

无论哪种框架，流程状态、幂等键、异常分类和审计记录都应落在明确的服务设计中，而不是散在路由函数里。

### 13. 轻量 ORM 使用时要注意什么？

**面试一句话：** Peewee 等轻量 ORM 能减少简单 CRUD 的样板代码，但仍需明确事务边界、连接生命周期、索引、批处理和 N+1 查询风险；复杂报表或性能敏感 SQL 应保留可解释和可优化的查询写法。

ORM 不会自动解决数据一致性或慢 SQL。生产排查仍要查看实际 SQL、执行计划和连接池指标。
