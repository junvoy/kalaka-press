# 车联网与实时通信面试题

本章对应简历中的 Netty、ECU 协议栈、MQTT、十万级设备在线和实时指令下发。它关注连接、协议、可靠投递与容量保护。

## Netty 与协议处理

### 1. Netty 为什么适合高并发网络服务？

**面试一句话：** Netty 基于 NIO 事件循环，用少量 I/O 线程管理大量连接，并提供编解码、管道、内存管理和背压等能力，适合连接多、消息短且需要低延迟的服务。

事件循环线程不应执行数据库慢查询或复杂计算；耗时业务应转交受控的业务线程池，避免阻塞同一线程管理的其他连接。

### 2. EventLoopGroup 与 ChannelPipeline 分别是什么？

**面试一句话：** EventLoopGroup 负责接收连接和处理 I/O 事件；每个 Channel 有自己的 Pipeline，入站消息依次经过解码、校验、业务处理等 Handler，出站消息反向经过编码器。

Handler 是否可被多个 Channel 共享取决于其是否保存连接私有状态。共享 Handler 必须无状态或正确标注可共享。

### 3. 为什么协议要有拆包和粘包处理？

**面试一句话：** TCP 只提供连续字节流，不保留业务消息边界，因此一次 read 可能只读到半包或多个包；协议必须通过长度字段、分隔符或固定长度等规则恢复完整消息。

最常见、可扩展的做法是“固定头部 + 长度字段 + 消息体”，并设置最大帧长，防止异常长度造成内存耗尽。

### 4. 心跳机制解决什么问题？

**面试一句话：** 心跳用于发现长连接是否仍然存活；服务端在连续未收到心跳或业务数据时关闭连接，客户端重连后重新认证和恢复订阅或状态。

心跳间隔要考虑网络抖动和设备功耗。一次心跳超时不一定代表设备永久离线，应结合连续次数和最后活跃时间判断。

### 5. MQTT 的 Topic、QoS 和保留消息怎么理解？

**面试一句话：** Topic 用于按层级路由消息；QoS 定义投递语义，QoS 0 最多一次、QoS 1 至少一次、QoS 2 协议层更严格但成本更高；保留消息让新订阅者能立即收到某个 Topic 的最后状态。

QoS 1 仍可能重复，因此设备指令和状态处理要有消息 ID、版本或幂等键。保留消息也不能误用于短期命令。

### 6. 设备指令下发怎样避免错发和重复执行？

**面试一句话：** 指令应携带设备 ID、业务请求号、命令版本和过期时间；服务端校验设备归属与当前状态，设备侧或平台侧记录最近已处理请求，实现幂等确认与可追踪重试。

特别是开锁、断电等不可逆或高风险指令，不能因网络超时就盲目重发；应查询最终状态或进入人工处置。

### 7. 十万级长连接的容量如何估算？

**面试一句话：** 需要同时估算每连接内存、心跳频率、入站消息速率、编解码 CPU、业务线程池、文件描述符和下游写入能力，并通过压测确认，而不是只按“连接数”判断。

连接数增长时，监控活跃连接、事件循环延迟、堆外内存、GC、丢包、重连风暴和队列积压。

### 8. 什么是背压？

**面试一句话：** 当生产速度超过消费者、网络或下游处理能力时，背压通过限制读取、队列边界、丢弃低优先级数据或限速来防止内存无限堆积。

实时遥测通常可以采样或合并旧状态；关键事件必须持久化、告警并按可恢复方式处理。不同消息不能使用同一种丢弃策略。

### 9. 实时链路 P99 延迟升高如何排查？

**面试一句话：** 按链路拆分网络、接入、解码、队列、业务处理、消息投递和存储耗时，结合连接数、GC、线程池队列和下游指标找瓶颈，再通过压测复现。

只看平均延迟会掩盖少数慢请求。对端到端延迟要求高的系统，应在每个关键阶段记录时间点并使用同一关联 ID 串联。
