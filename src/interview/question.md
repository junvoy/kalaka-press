# 后端技术地图与学习路径

本宝典按“知识域”归类，而不是只按框架名称平铺。它把语言基础、应用开发、数据、系统能力、工程交付和业务领域分开：同一个概念只有一个主归属，其他章节只做链接，不重复维护答案。

这样的安排吸收了两类成熟资料的优点：JavaGuide 用面试优先级组织复习路径，CS-Notes 用稳定的知识域组织长期查阅。本站把两者结合为“目录按知识域、学习按优先级”。

## 技术架构路线

| 知识域 | 章节 | 主问题 | 边界 |
| --- | --- | ---: | --- |
| Java 核心 | [Java 核心学习目录](./java/question) | Java 语言、并发和 JVM 怎样写出正确代码 | 不收录 Spring、ORM、分布式中间件 |
| 计算机与应用基础 | [网络与 I/O](./web/io-network) | 请求、连接、协议和文件怎样流动 | 不讲具体框架的注解与配置 |
| 应用框架与数据访问 | [Spring](./spring/question) · [MyBatis](./persistence/mybatis) | 服务如何组织 Web 请求、事务和对象映射 | 不讲数据库的存储引擎、索引实现 |
| 数据存储与缓存 | [MySQL](./mysql/question) · [Redis](./redis/question) | 数据怎样持久化、索引、事务与加速访问 | 不把消息可靠性混入缓存章节 |
| 消息与系统集成 | [消息队列](./middleware/mq) · [配置、调度与数据集成](./integration/question) | 异步事件、批处理和异构系统怎样可靠协作 | 不承载跨服务一致性理论 |
| 分布式与微服务 | [分布式系统设计](./distributed/question) · [微服务治理](./microservices/question) | 多节点一致性、可用性与服务治理如何取舍 | 通用理论与具体组件分别讲 |
| 工程化与交付 | [工程实践](./engineering/question) · [可观测性与交付](./operations/question) | 怎样测试、发布、观测和恢复系统 | 不展开业务协议细节 |
| 业务领域与协作 | [车联网](./iot/question) · [Vue 3](./frontend/question) | 特定领域协议与前后端协作怎样落地 | 可随真实项目增设新领域 |

::: tip 建议的第一轮学习顺序
项目/简历相关题 → Java 核心 → MySQL 与 Redis → Spring → 网络与 I/O → 消息与系统集成 → 分布式与微服务 → 工程化与交付。车联网、前端协作等领域题，按目标岗位与项目经历插入复习。每章先掌握前 3 到 5 道高频题，再回头补充追问。
:::

## 怎样回答技术架构类面试题？

先说明它处于哪一层、解决什么问题，再说明核心机制和一个边界条件。例如谈消息队列时，不能只说“异步和削峰”，还要说明重复消费如何幂等、失败消息怎样重试和告警。

新增或改写题目时，请遵循[面试题内容编写规范](./content-guide)。
