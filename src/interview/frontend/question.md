# Vue 3 与运营平台协作面试题

本章对应简历中的 Vue 3、Element Plus 和运营平台端到端交付。重点是前后端接口协作和基础原理，不把前端经验包装成专职前端架构经验。

### 1. Vue 3 的 Composition API 有什么价值？

**面试一句话：** Composition API 让相关状态、计算属性、副作用和复用逻辑可以按功能组织，而不是分散在 data、methods 等选项中，复杂页面更容易拆分和复用。

### 2. `ref` 和 `reactive` 怎么选？

**面试一句话：** ref 适合基本类型或需要整体替换的值，通过 `.value` 访问；reactive 适合对象代理。解构 reactive 对象可能丢失响应性，需要使用 toRefs 等方式处理。

### 3. computed 和 watch 的区别？

**面试一句话：** computed 用于根据已有状态推导新值并缓存；watch 用于监听变化后执行副作用，例如重新查询数据。不要用 watch 代替简单派生计算。

### 4. Vue 路由守卫适合做什么？

**面试一句话：** 路由守卫可在进入、离开或解析路由前检查登录态、权限和未保存修改；服务端仍必须校验权限，前端守卫只改善体验，不能作为安全边界。

### 5. 运营平台如何设计权限控制？

**面试一句话：** 前端根据用户权限展示菜单和操作入口，后端以用户身份和资源范围做最终鉴权；按钮隐藏不能替代接口权限校验，审计操作还应记录操作者和业务对象。

### 6. Element Plus 表格大数据量怎样处理？

**面试一句话：** 使用服务端分页、筛选和排序，明确稳定排序键；超长列表可考虑虚拟滚动。不要把全量数据一次拉到浏览器后再过滤。

### 7. 前后端接口怎样处理异常和幂等？

**面试一句话：** 约定统一错误码、可读提示、字段校验错误和关联 ID；创建或提交操作携带幂等键，按钮防抖只是体验优化，后端必须保证最终幂等。

### 8. 配置发布页面怎样避免误操作？

**面试一句话：** 展示变更 diff、影响范围和版本号，对发布、回滚等高风险操作二次确认并校验权限；发布结果、失败原因和回滚入口应可追溯。
