# 可观测性与交付面试题

本章对应简历中的 Prometheus、Grafana、SLS、Linux、Docker、Jenkins、Kubernetes 和 Nginx。它关注服务上线后如何看见问题、稳定变更和快速恢复。

## 监控与运维

### 1. 日志、指标和链路追踪分别回答什么问题？

**面试一句话：** 日志记录具体事件细节，指标反映趋势与告警，链路追踪展示一次请求跨服务的耗时与依赖；三者配合定位问题，不能互相完全替代。

例如错误率升高先由指标告警，再用 trace 找慢依赖，最后用关联 ID 查结构化日志。

### 2. Prometheus 的拉取模型有什么特点？

**面试一句话：** Prometheus 定期从服务暴露的 metrics endpoint 拉取时序指标，再通过 PromQL 查询和 Alertmanager 告警；拉取模型便于统一发现目标和检查采集健康。

指标标签不能放用户 ID、订单号等高基数字段，否则时间序列数量会爆炸。业务明细应进入日志或追踪系统。

### 3. Grafana 仪表盘应关注哪些核心信号？

**面试一句话：** 优先看请求量、错误率、延迟分位数和资源饱和度，再补充 JVM、线程池、连接池、队列积压和下游依赖；关键流程还要有业务成功率和未收敛任务数。

只看 CPU 或平均耗时往往不够。高并发服务应重点观察 P95/P99 和队列增长趋势。

### 4. 告警怎样避免噪声？

**面试一句话：** 告警应以用户影响和可行动性为中心，使用持续时间、分级、聚合与抑制减少瞬时抖动；每条重要告警都应有负责人、排查入口和处理预案。

“任何异常都通知所有人”会导致告警疲劳。低优先级趋势可进看板，高风险且需立即动作的问题才应打扰值班人员。

### 5. Docker 镜像怎样构建得更安全稳定？

**面试一句话：** 使用固定基础镜像版本、多阶段构建、最小运行时依赖和非 root 用户，镜像中不写入密钥；构建产物与配置分离，并记录可追溯版本。

容器不是虚拟机。不要在一个镜像中同时运行多个无关进程，也不要把日志只写在易丢失的本地文件。

### 6. Kubernetes 的 Deployment、Service 和 Ingress 分别做什么？

**面试一句话：** Deployment 管理无状态 Pod 的副本和滚动更新，Service 提供稳定的服务发现入口与负载均衡，Ingress 负责把外部 HTTP(S) 请求按域名和路径转发到 Service。

资源 requests/limits、健康检查和优雅终止是稳定运行的关键；没有它们，扩缩容和滚动发布容易造成抖动。

### 7. Nginx 常用来做什么？

**面试一句话：** Nginx 常作为反向代理、静态资源服务、TLS 终止、负载均衡和限流入口；它应设置上游超时、请求体限制和可信转发头，避免把错误直接放大到后端。

代理重试要谨慎，尤其写请求。重试可能让后端执行两次，必须结合幂等设计。

### 8. Jenkins CI/CD 的基本流水线是什么？

**面试一句话：** 常见流水线包括拉取代码、依赖与静态检查、单元/集成测试、构建镜像、漏洞或配置扫描、部署到环境、健康验证和灰度推广；失败应阻断后续阶段并保留可追溯日志。

密钥应由凭据系统或运行环境注入，不能硬编码在 Jenkinsfile 或构建日志中。

### 9. Linux 上 Java 服务异常先查什么？

**面试一句话：** 先确认进程、端口、日志、CPU、内存、磁盘、网络和文件句柄，再结合 JVM 指标、线程转储和 GC 日志定位；排查应先采集证据，避免直接重启破坏现场。

常见命令包括 `top`、`ps`、`ss`、`df`、`lsof` 和 `jstack`，但线上执行必须遵循权限与变更规范。

### 10. 如何做安全回滚？

**面试一句话：** 回滚要覆盖代码、配置、镜像和数据库兼容性：先停止扩大影响，切回已验证版本或开关，再核对消息、缓存和异步任务是否产生不一致，并通过指标确认恢复。

数据库 schema 变更优先向前兼容。删除字段、变更消息结构等不可逆操作不能和应用发布绑在同一步完成。
