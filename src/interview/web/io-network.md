# Web 与网络面试题

I/O 是程序与文件、网络、数据库等外部世界交换数据的方式。本章先分清阻塞和非阻塞，再理解 NIO、HTTP 和连接复用。

## I/O 基础与 NIO

### 1. 什么是阻塞 I/O 和非阻塞 I/O？

**面试一句话：** 阻塞 I/O 在数据尚未准备好时会让当前线程等待；非阻塞 I/O 会立刻返回，调用方可稍后重试或交给事件循环处理。

“非阻塞”不等于“整个请求不耗线程”。真正的收益取决于是否通过事件驱动和 I/O 多路复用，让少量线程能管理很多连接。

### 2. BIO、NIO 和 AIO 有什么区别？

**面试一句话：** BIO 以阻塞流为主，模型直观但大量连接常需大量线程；NIO 用 Channel、Buffer 和 Selector 实现非阻塞与多路复用；AIO 把异步完成结果通过回调或 Future 通知调用方，实际使用要看操作系统和框架支持。

| 模型 | 常见特点 | 适合场景 |
| --- | --- | --- |
| BIO | 一个连接的读写会等待 | 连接较少、代码简单的场景 |
| NIO | 少量线程监听多个就绪连接 | 高并发网络服务 |
| AIO | I/O 完成后通知 | 特定异步文件或网络场景 |

### 3. NIO 的 Buffer、Channel、Selector 分别是什么？

**面试一句话：** Buffer 是读写数据的缓冲区，Channel 是数据通道，Selector 用一个线程监听多个 Channel 的就绪事件，从而避免为每个空闲连接阻塞一个线程。

![NIO Selector 监听连接和分发事件的流程](/.image/interview/web/io-network/nio-selector-flow.svg)

Buffer 的常见状态是 `position`、`limit`、`capacity`。写完后调用 `flip()` 才能切换为从头读取；读完准备再次写入时通常调用 `clear()` 或 `compact()`。这是 NIO 初学者最常见的错误点。

### 4. 什么是 I/O 多路复用？

**面试一句话：** I/O 多路复用让一个线程同时等待多个连接的可读、可写等事件，只有就绪的连接才交给程序处理，因此能降低大量空闲连接的线程等待成本。

在 Linux 上常见底层机制是 epoll，macOS 常见 kqueue。它们是操作系统能力；Java NIO 的 Selector 是跨平台抽象，具体实现随系统和 JDK 而变化。

### 5. 零拷贝是什么？

**面试一句话：** 零拷贝是尽量减少数据在内核空间和用户空间之间的复制、上下文切换或 CPU 参与，以提高大文件传输等场景的吞吐量；它不一定真的完全没有任何复制。

例如 `FileChannel.transferTo` 可以让内核更直接地把文件数据交给网络协议栈。是否生效取决于操作系统、文件类型和 JDK 实现，应该通过实际指标验证。

### 6. Java 中怎样正确读写文件？

**面试一句话：** 小文件可使用 `Files` 的便捷方法；大文件应流式读取或按块处理，并使用 try-with-resources 确保流和 Channel 被关闭。

读写文本时要显式指定字符集，例如 UTF-8，避免依赖机器默认编码。上传文件还要限制大小、校验类型，并避免把用户输入直接拼成文件路径，防止路径穿越。

## HTTP、TCP 与连接管理

### 7. TCP 和 UDP 有什么区别？

**面试一句话：** TCP 面向连接、可靠且有序，通过确认、重传和流量控制保证传输；UDP 无连接、报文边界明确、开销更小，但不保证送达和顺序。

网页、数据库连接通常使用 TCP；实时音视频、游戏等可容忍少量丢包且追求低延迟的场景可能使用 UDP 或在其上构建可靠协议。

### 8. TCP 三次握手和四次挥手为什么这样设计？

**面试一句话：** 三次握手让双方确认彼此的收发能力并同步初始序号；关闭时 TCP 是全双工的，一方发送 FIN 后仍可接收对方剩余数据，因此常需要双方分别关闭，表现为四次报文交换。

不要把次数当作脱离语境的死记结论：报文可能合并，异常断连也可能走 RST。关键是理解“建立时确认双向通信，关闭时两个方向可独立结束”。

### 9. HTTP 和 HTTPS 有什么区别？

**面试一句话：** HTTPS 是 HTTP 运行在 TLS 之上，通过证书校验和加密保护传输的机密性、完整性与服务端身份；它不是“把 HTTP 请求内容简单加密一下”。

TLS 握手会协商协议和密钥，并验证证书链。生产环境应正确校验证书和主机名，不能为了绕过测试问题而信任所有证书。

### 10. HTTP 1.1、HTTP/2 和 HTTP/3 的主要区别？

**面试一句话：** HTTP/1.1 常通过持久连接复用 TCP 连接但应用层仍有队头阻塞问题；HTTP/2 在一个 TCP 连接上用二进制分帧多路复用；HTTP/3 基于 QUIC/UDP，减少 TCP 层队头阻塞并改进连接迁移。

协议升级不等于接口必然更快。仍需关注服务端实现、TLS、代理层、连接数和请求本身的耗时。

### 11. 什么是 HTTP 幂等？POST 一定不幂等吗？

**面试一句话：** 幂等表示同一请求执行一次和执行多次的最终业务效果相同；HTTP 方法的语义只是惯例，POST 默认不保证幂等，但业务完全可以通过幂等键实现幂等。

例如创建订单时，客户端携带唯一请求号，服务端通过唯一约束或幂等记录确保重复提交只得到同一笔订单。不要只靠“前端按钮置灰”保证幂等。

### 12. 什么是连接池？为什么需要设置超时？

**面试一句话：** 连接池复用数据库或 HTTP 连接，避免频繁建连成本，同时限制并发连接数以保护下游；连接、读取和整体调用都应有明确超时。

没有超时的慢请求会长期占用线程和连接，最终让整个服务排队。超时后是否重试要看操作是否幂等、下游是否过载，并采用有限次数和退避策略。
